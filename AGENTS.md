Guidance for anyone, human or AI agent, working in this repository. Read this first, then the skill for the task you are doing (see "Skills" below). This file is the repo map: if you add, move or retire a top-level folder, update the table in the same PR.

## Project summary

OpenTriage is a personal hub for open source. Contributors find repos, issues, programs and bounties that fit them. Maintainers see what needs them across the repos they maintain. Everything runs on free tiers and live public APIs (no hand-kept lists).

- Live frontend: `frontend_new/` (Vite + React 18, react-router 6, Tailwind, Radix/shadcn, framer-motion), deployed on Vercel.
- Live backend: `backend-ts/` (Next.js 16 API routes behind a custom `server.js` with socket.io), Drizzle ORM on libSQL/Turso (embedded replica).
- Auth: GitHub OAuth, then an OpenTriage JWT. GitHub calls for a user use **that user's own token**.
- Work only on the feature branch (`feat/workspace-ui`), never `main`, until it is approved to merge.

## Build and test

```bash
cd backend-ts && npm test          # Jest: rules, adapters, skill evals
cd backend-ts && npm run lint
cd backend-ts && npm run build
cd frontend_new && npx vitest run  # frontend tests
cd frontend_new && npm run build
```

DB schema change: edit `backend-ts/src/db/schema.ts`, then `npm run db:generate` and commit the migration.

## Rules that are easy to get wrong

- **Per-user tokens.** User-specific GitHub calls go through `withGitHub(request)` in `lib/github/route-helpers.ts`. Server-side work on public data (opportunities sync, public issue, badge) uses `serverOctokit()` / `serverToken()` from `lib/github/octokit.ts`, which picks the least-used token from `GITHUB_TOKENS` (comma-separated) plus `GITHUB_TOKEN`. Never read `process.env.GITHUB_TOKEN` directly.
- **Build GitHub clients with `createGitHubClient()`**, never `new Octokit()`: it adds ETag conditional requests (304s are free) and records each token's rate budget.
- **Many instances are normal.** `cached()` checks memory, then the shared `cache_entries` table in Turso, then GitHub. Only plain JSON values are shared. Background jobs run through `runExclusive(name, ttlMs, fn)` in `lib/jobs.ts` so only one instance runs them. Turn the shared tier off with `SHARED_CACHE=off`.
- **Never show a spinner for data we already have.** Frontend reads use `useQuery(key, fetcher, { staleMs })`, which returns cached data first and refreshes in the background.
- **A failing source never wipes data.** The opportunities sync keeps a source's previous rows when it errors.
- **Pure rules stay pure.** Anything in `lib/coordination/` and `lib/opportunities/normalize.ts` takes plain data and returns plain data, so it can be tested and run as evals.
- **No paid APIs or tiers.** AI features use the user's own key.

## Every PR: the work and the learning

Each PR carries two things, in the same PR:

1. **The work, with evidence:** a test, or a short note of how you verified it.
2. **The learning:** if you discovered something non-obvious (a trap, a workaround, a convention), add it to the skill for that area. New edge cases go into that skill's `evals.json`.

Don't write back one-off notes or things obvious from the code. Fill in the PR template, including the AI disclosure.
